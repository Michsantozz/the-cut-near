## Project rules

- The rules of the game, every number and every refusal, are in `RULES.md`. The contract enforces them; the app, the
  simulation and the docs follow them. Change a rule only in `RULES.md`, the contract and its tests together.
- `docs/contract-interface.md` is the contract between `contracts/` and the app. Change it only together with both sides.
- Architecture and import rules are in `docs/ARCHITECTURE.md` (app → features → entities → shared). ESLint enforces them.
- Tests live in `tests/`, never next to source files; `tests/unit` mirrors `src/`. Contract tests live in
  `contracts/thecut/src/tests/`.
- Screens match the approved mockups in `docs/design/source/<Screen>.dc.html`. `docs/design/archive/` holds earlier rule sets
  for history only: never take a rule or a number from it.
- `sim/RESULTS.md` and `src/features/inside/data/sim-v20.json` are generated by `pnpm sim:write`. Never edit them by hand.
- `deploy/testnet-*.json` record real launches. Never edit them by hand; `scripts/testnet/launch.ts` writes them.
- A claim in the README or on the judge desk names the code and the test that prove it. Keep both pointing at real lines.
- UI components come from shadcn/ui in `src/shared/ui` (add with `pnpm dlx shadcn@latest add <name>`), themed to the design. Do not add another component library.
- Wallets: NEAR Connect only (`@hot-labs/near-connect`, `near-connect-hooks`). NEAR Wallet Selector is deprecated: never add it.
- AI: NEAR AI Cloud with a Private model only, so answers are signed inside a TEE. No other AI provider.
- Read `node_modules/next/dist/docs/` for any Next.js API you use (Next 16, `cacheComponents` is on).
- Never add a migration by hand or in parallel branches: change `db/schema.ts`, then run `pnpm db:generate` once on main.
- Secrets live in env vars, never in the repo. Never deploy to mainnet, sign mainnet transactions or make the repo public without the human.
- All code, comments, docs and commit messages in English.
